# Super Arthur World authoring playbook

This is the project's own authoring context, not Compozy OS runtime memory. Read `AGENTS.md` and the active `_idea.md` before authoring. User instructions override imported skills.

- Separate product behavior from technical design; Supabase and Vercel are fixed user constraints, not newly selected implementation choices.
- Full requested gameplay scope; no invented MVP boundary or reduction for document size.
- Non-commercial AI programming experiment. Favor straightforward design, validated frameworks, quality open-source references and bug prevention over enterprise infrastructure.
- Product decisions from interview answers are binding. Routine author choices must be labeled defaults and remain reviewable. Latest corrections supersede earlier answers.
- Documents follow the local PRD/story and Techspec/test templates. No business KPIs, monetization assumptions or rollout targets. Use observable acceptance criteria.
- Preserve permanent requirement, story and test IDs. Each reference mechanic needs a corresponding game behavior, story and eventual owning test/task.
- Interviews are in plain Portuguese, one consequential decision at a time. Do not ask the user to decide routine unfamiliar programming details.
- Native Codex subagents implement, review and fix. No Compozy/Herdr runtime. Commits, push, deploy and MCP usage are already authorized.
- Independent final QA before publication and verification of the live Vercel build afterward.
- Imported preflight requirements about Compozy plugins, UDS, config.toml lifecycle and operator ecosystems are not game features. Record no impact where applicable; do not create those systems to satisfy upstream templates.
- Imported references to Compozy's own missing memory and CLAUDE.md do not block this project: this playbook, AGENTS.md and the confirmed brief are the applicable context.
