# ADR-006: Dedicated integrations and optional Google sign-in

## Status
Accepted

## Date
2026-10-11

## Context
The user chose Supabase, Vercel, public GitHub repository super-arthur-world, optional Google accounts and a dedicated database project. Infrastructure access is authenticated, but that does not configure the game's Google OAuth provider. The user confirmed a US$0 Free plan.

## Decision
Create/verify dedicated game resources, using the user's newly selected Supabase organization nmxzxcwfywduntcfhyfy on the Free plan, Vercel static build and the public game repository. The user superseded the earlier organization selection on 2026-10-11. The dashboard confirms dedicated project elbdwupwmnrssyemexrg, named super-arthur-world, in us-west-2. Use Supabase Google OAuth with PKCE and owner-RLS saves. Guests play without registration. Continue loaded play/local saves during connection loss; full offline reopen is not required. Keep provider secrets outside the app/repo and account callbacks allowlisted.

## Alternatives Considered
### Existing unrelated Supabase project
Would avoid provisioning but contradicts the user's dedicated-resource choice.
### Mandatory login or email/password
Adds prerequisites or a different auth method; not selected.
### Full offline PWA and custom auth server
Adds cache/version/provider complexity without a confirmed requirement.

## Consequences
### Positive
Straightforward static deployment, isolated account data and immediate guest access.
### Negative
Google Cloud client credentials/provider setup are an external dependency for real account QA.
### Risks
Cost MCP queries/confirmation were unavailable; the user confirmed US$0/Free and created the dedicated project through the dashboard. The MCP still lists the former account's resources, pending the user's reconnection; do not modify that account's unrelated project. Database migrations, RLS and Google provider configuration remain unverified. Google credentials are presently unavailable; continue unaffected implementation and report the precise requirement.

## Implementation Notes
Only public Supabase URL/publishable key enter Vite env. Existing commit/push/deploy authorization persists. A guest-only build cannot be labeled complete for the full PRD while account QA is blocked.

Verified Vercel setup: official CLI 63.1.2 created and inspected project prj_FR4IHo9acL1ucdgRfbgDO7iA71Ei (super-arthur-world) in Hobby team team_m0FjP3deRHLnxahFVQG3l6Sz (lucas-bf) after user login. Vite, pnpm frozen install, pnpm build, dist and Node 24.x are configured; the local directory link resolves to this exact project. Credentials and CLI files remain ignored; no deployment has occurred. The user reported Supabase reconnection, but direct MCP access to elbdwupwmnrssyemexrg still returned no permission. Verified dashboard access is an acceptable task-05 fallback with versioned migration files and actual RLS evidence.
