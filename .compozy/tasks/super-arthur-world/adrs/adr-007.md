# ADR-007: Authored content, pinned reference reuse and independent QA gates

## Status
Accepted

## Date
2026-10-11

## Context
The experiment requires every mechanical family and 120 original levels, while avoiding enterprise process. The user explicitly requested open-source code research, autonomous native subagents, independent reviews/corrections and final QA before publication.

## Decision
Author Tiled JSON maps and a validated catalog covering 12 worlds, 120 distinct layouts, 150 exits and 600 medallions. Use original assets with a provenance manifest. Adapt inspected code at pinned revisions with license attribution, never treating source code licenses as asset permission. Use seven implementation tasks plus QA plan and independent QA execution tasks, native Codex delegation and correction loops. Publish after relevant QA blockers are resolved, then verify actual live build and guest/account journeys.

## Alternatives Considered
### Seeded cosmetic layout repeats
Quickly reaches a count but does not satisfy meaningful original campaign layouts.
### Reuse a complete Mario clone/asset pack indiscriminately
Does not prove mechanics or licensing and conflicts with original identity/content.
### Compozy execution runtime or enterprise operator tooling
Explicitly excluded; workflow skills and ordinary project scripts suffice.

## Consequences
### Positive
Auditable scope, reproducible failures and evidence tied to the shipped revision.
### Negative
Content authoring and full QA remain substantial work.
### Risks
Automated reachability/uniqueness checks cannot prove human playability. Require representative actual play, full campaign structural audits, defined completion journeys and reference coverage. Physical-device limitations and missing OAuth evidence remain honest gaps, never passes.

## Implementation Notes
Pin template d1d7d58acfcf47f97642bcb8b4967071b85f8db9 and Celeste reference 1b0ce45c75e05649ae91b44a8bb6b196684e4352. No production debug progression unlocks. Final QA and remediation agents differ from implementation agents. Test IDs belong to exactly one implementation/QA task.
