# ADR-004: Phaser static app and single-authority fixed-step gameplay

## Status
Accepted

## Date
2026-10-11

## Context
The complete browser platformer requires slopes, one-way/moving/rotating surfaces, mount, controlled flight, multiple inputs and 120 levels. The repository has no existing code architecture. Popularity alone does not prove a suitable platform controller; inspected frameworks do not supply all reference mechanics.

## Decision
Use Phaser 4.2.1, TypeScript and Vite in one static app with accessible DOM menus. Phaser manages rendering/cameras/assets/audio; pure TypeScript gameplay owns positions and collisions at fixed 60Hz. Use a small explicit kinematic solver with swept/substep movement, tile slope profiles, contact grounding and moving-surface support. Prove this base in collision fixtures before expanding campaign content. No React, custom app server, generic ECS or mixed position authorities.

## Alternatives Considered
### Phaser Arcade as complete physics
Simple infrastructure and common examples, but rectangular/circular bodies do not implement required slopes. Rejected as the sole terrain solver; no fabricated slopes through rectangular approximation.
### melonJS built-in platformer
Polygon/SAT geometry and an official slope example offer real reusable ideas. Inspected tag 20.8.0 tests expose falling/grounded and time-step semantics that still demand a controller contract. Rejected as a shortcut assumed to prove all SMW mechanics; remains a useful algorithm/test reference.
### PixiJS or Matter rigid-body controller
Pixi requires assembling more game infrastructure; Matter provides polygons but needs platform-specific control/contact tuning. Neither reduces this project's total implementation risk enough to replace Phaser plus explicit gameplay rules.

## Consequences
### Positive
One testable movement authority and substantial mature browser infrastructure reuse.
### Negative
The kinematic controller is implementation work and is not already validated.
### Risks
Slope seams/dynamic carry/crush/form growth/mount/flight interactions can fail. Gate these with deterministic 30/60/120 render schedules and real collision evidence; repair/reconsider solver without deleting scope.

## Implementation Notes
Pin exact dependency versions/lockfile. Core imports no browser/engine APIs; adapters consume state. Never let Phaser physics or tweens compete for actor positions. See Techspec numeric contracts and test catalog.
